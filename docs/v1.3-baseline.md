## Budget for v1.3

`scripts/bundle-budget.mjs` measures with `node:zlib` at level 9, which reads ~480 B higher
than GNU `gzip -9` on the same bytes. Measured that way the v1.2.0 entry is **123,061 B**,
and that is the number the script compares against — the two must never be mixed.

* **First-paint gzip ceiling: 128,181 bytes** (123,061 + 5 × 1024).

  Raised in v1.5 from 127,157, by the one kibibyte `docs/v1.5-plan.md` budgets for the
  interactive tutorial under "Gates". Three things have to be paid for before first paint and
  cannot be deferred: the first-run check, the `?learn` parser, and the "?" buttons beside the
  controls that have a lesson behind them — plus the repository context every component now
  reads its product and observation writes from, which is what keeps a lesson off the
  shopkeeper's own data. Everything else in the tutorial — the Learning Centre, onboarding, the
  coach, the practice store, the progress store — is behind `await import()`.

  Measured on the same machine with this script, building the `v1.4.1` tag in a worktree and the
  branch beside it: v1.4.1 reads **126,651 B** and v1.5 **127,313 B**, so first paint grows by
  **662 B** — 362 B inside the kibibyte. The language chunks do not move (3,037 → 3,036 B),
  because every tutorial string lives in the lazy sheets bundle.

  (An earlier figure of 568 B in this file was taken before the mission and the last round of
  strings landed. The two numbers were measured against different trees, not different rulers.)

  That number is net. The tutorial's own entry surface costs about **2,110 B**, and **1,509 B**
  of it was paid for by splitting `src/components/Icons.tsx`. That module is shared between the
  entry chunk and every lazy sheet, so Rollup hoisted all thirty-four glyphs into the entry:
  a shopkeeper who never opened a sheet was downloading the icons for one. Ten stayed; the other
  twenty-four moved to `SheetIcons.tsx` and are re-exported from `Icons.tsx`, so no import site
  changed and nothing else had to move.

  **877 B of the new kibibyte are unspent.** The obvious next 150 B, if it is ever needed: the
  `TOUR_SHEETS` and `TOUR_ACTIONS` name lists in `src/learn/coach/events.ts` are hoisted into the
  entry for the same reason the icons were — only lazy chunks read them — and the same split
  would move them out.

  Raised once before, in v1.4.1, from 126,133 (baseline + 3 KiB). v1.4.0 shipped a single error
  boundary around the whole app, so one database failure replaced the entire screen — including
  the calculator, which touches no storage. Splitting that into an app-level boundary and a
  feature-level one, and detecting whether the fault really is storage instead of telling every
  user to turn off private browsing, costs about 650 B of entry chunk.

  That cost cannot be deferred: a boundary whose fallback lives in a lazy chunk is no boundary
  at all, because the fetch that would load it can fail for the same reason the app did. The
  alternative to spending the bytes was leaving users of a locked-down browser with no app, so
  the ceiling moved rather than the guarantee.
* The metric is **entry chunk + the largest language chunk**, not the entry alone. v1.3 moves
  translations out of the entry into one chunk per language, so measuring the entry by itself
  would understate what a user actually downloads and would turn the budget into a shell game.
* Every new surface (installment schedule, products view, backup, What's New) must be a
  separate lazy chunk, not part of the entry.

## Environment facts verified

* `vite-plugin-pwa@0.21.2` does expose `RegisterSWOptions.onRegisteredSW(swScriptUrl, registration)`
  (`node_modules/vite-plugin-pwa/types/index.d.ts:18`) — Feature D can rely on it.
* Chromium for Playwright: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`
  (already hard-coded in `scripts/screenshots.mjs` and `scripts/verify-offline.mjs`).
* There is **no existing Jalali date utility** in the repo, contrary to the brief.
  `HistorySheet` gets Jalali dates for free from `Intl.DateTimeFormat('fa-IR')`, whose default
  calendar is `persian`. v1.3 adds `src/lib/dates.ts` wrapping exactly that — no new dependency.
